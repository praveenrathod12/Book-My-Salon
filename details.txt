# Build a Full-Stack Salon Booking Application

## 1. Project Goal

Build a complete, professional full-stack web application for salon discovery and appointment booking.

The application solves this real-world problem:

Customers often visit salons without knowing whether the salon is currently busy. They may have to wait for a long time even though another nearby salon has available capacity.

The application should allow customers to:

* Discover salons.
* View salon details.
* See available services.
* See available barbers.
* See available appointment slots.
* View availability for the entire upcoming week.
* Select a service.
* Select a date and time.
* Book an appointment.
* View booking details.
* Cancel or reschedule an appointment.
* View booking history.

Salon owners should be able to:

* Register their salon.
* Manage salon information.
* Set salon working hours.
* Add and manage barbers.
* Activate/deactivate barbers.
* Configure barber schedules.
* Add services.
* Set service prices and duration.
* View appointments.
* Manage appointments.
* View daily and weekly schedules.
* View basic dashboard statistics.

The core feature of this application is a **dynamic salon availability and booking system**.

Implement JWT-based authentication.

The backend should provide:

```text
POST /api/auth/register
POST /api/auth/login
POST /api/auth/refresh-token
```

Use password hashing.

Never store plain-text passwords.

Login response should contain:

```json
{
  "accessToken": "...",
  "refreshToken": "...",
  "user": {
    "id": 1,
    "name": "John",
    "email": "john@example.com",
    "role": "CUSTOMER"
  }
}
```

Roles:

```text
CUSTOMER
SALON_OWNER
```

Implement:

### Angular

```text
AuthService
AuthGuard
RoleGuard
AuthInterceptor
```

The interceptor should automatically add:

```text

```

to authenticated HTTP requests.

Protect routes according to user role.

# 16. CORE FEATURE — DYNAMIC SLOT AVAILABILITY

This is the most important business logic.

Do NOT simply hardcode appointment slots.

Availability must be calculated using:

```text
Salon working hours
+
Barber working schedule
+
Barber active status
+
Barber leave/unavailability
+
Barber service capability
+
Existing appointments
+
Service duration
```

Example:

Salon:

```text
09:00 AM - 09:00 PM
```

Service:

```text
Haircut
30 minutes
```

Barbers:

```text
Barber A → Active
Barber B → Active
Barber C → Active
```

At 5:00 PM:

```text
Barber A → Available
Barber B → Booked
Barber C → Available
```

Therefore:

```text
5:00 PM → 2 available barbers
```

If another customer books Barber A:

```text
Barber A → Booked
Barber B → Booked
Barber C → Available
```

Then:

```text
5:00 PM → 1 available barber
```

If all three are occupied:

```text
5:00 PM → Fully Booked
```

Slot calculation must respect service duration.

Example:

```text
Haircut = 30 minutes
Hair Spa = 60 minutes
```

The availability engine must calculate overlapping appointments correctly.

---

# 19. PREVENT DOUBLE BOOKING

This is critical.

Two customers must never successfully book the same barber for overlapping time periods.

The backend must always re-check availability immediately before creating an appointment.

Do NOT trust frontend availability.

Booking flow:

```text
Customer selects slot
        ↓
Frontend sends booking request
        ↓
Backend validates request
        ↓
Backend checks availability again
        ↓
Backend identifies available barber
        ↓
Backend creates appointment
        ↓
Return confirmation
```

If the slot is no longer available:

Return:

```text
409 Conflict
```

with a message such as:

```text
"The selected time slot is no longer available."
```

Use database transactions where appropriate.
